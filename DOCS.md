# Документация — что куда пишем

Слои и правило для каждого. Проверено инвентаризацией 2026-08-13: три агента
прошли все md репозитория, мёртвое вынесено в `archive/`, phase-папки удалены.

## Слои

| Слой | Файлы | Правило |
|---|---|---|
| **Состояние** | `STATE.md` | Источник правды. При расхождении с любым доком верить коду, потом STATE. Карта всех доков — Часть VI. Доведён компонент → правка STATE в том же заходе |
| **Навигация** | `README.md` | Только layout репозитория и точки входа. Не дублирует содержание |
| **Вижен** | `VISION.md` | Точка Б и рамка для решений: обещание, конституция, домен, экономика, оси. Меняется редко и только решением владельца. Не описывает состояние (это `STATE.md`) и не ведёт реестр идей (это `product-ideas.md`) |
| **Решения** | `product-ideas.md` | Каждое продуктовое решение: имплементируем / отложено / убито, с причиной. Решение, не попавшее сюда, будет переспорено заново |
| **Релиз** | `CHANGELOG.md`, `RELEASE-N.md` | CHANGELOG: поменял поведение — строка в том же коммите. RELEASE-N: план релиза с гейтами; после выхода релиза переезжает в `archive/` |
| **Хендофф** | `NEXT-STEPS.md` | Лог одной сессии/темы, чтобы продолжить без контекста. Влитое в STATE/код — вычищается, файл не растёт бесконечно |
| **Канон** | `meeting-recorder/docs/` (SPEC, ARCHITECTURE, AUDIO-CAPTURE-CASES), `design/` | Спецификации, на которые ссылается код (в т.ч. doc-комментариями). Планы после выполнения → `archive/` |
| **Эксперименты** | `docs/*_EXPERIMENTS.md`, `tools/*/README.md` + `OPTIMIZATION.md` | README лаборатории = история замеров, OPTIMIZATION = текущая доска. Числа из них не копируются в другие доки — только ссылка. Потерявший актуальность журнал → `archive/` |
| **Артефакты** | `swift/benchmarks/report-*.md`, `tools/recap-lab/out/` | Перезаписываемые результаты прогонов — данные, не документация. Не читать как справку |
| **Архив** | `archive/` | Заморожен. Не редактируется под текущее состояние (дописывание в планы — механизм дрейфа). Вход через `archive/README.md`; при переносе туда — строка в его таблицу |
| **Рабочий лог** | `WORKLOG.md` | Что сделано, зачем, как проверено, что осталось — по каждому куску работы, новейшее сверху |

## Правила

1. **Новый файл — последнее средство.** Сначала ищи слой выше. Новый док
   создаётся, только если не влезает ни в один, и в том же коммите вносится
   в карту доков (`STATE.md`, Часть VI).
2. **Смерть дока — это переезд.** План выполнен / журнал устарел → `git mv` в
   `archive/`, строка в `archive/README.md`, входящие ссылки обновить. Не
   удалять: архив — трассируемость решений.
3. **Один факт живёт в одном месте.** Числа замеров — в лаборатории, поведение —
   в SPEC, состояние — в STATE. Везде ещё — ссылкой, не копией.
4. **Дата у всего исторического.** Раздел или файл, верный «на момент» — говорит
   этот момент в заголовке; иначе это будущий обман.
