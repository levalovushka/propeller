# Замер живого слоя: сколько стоит скорость

Живая строка кормит `gigastt` порциями звука, и **размер порции решает
качество**: чем короче кусок, тем меньше у распознавания контекста и тем сильнее
речь рассыпается на огрызки. Это не рассуждение, а замер — и вот чем он делается.

## Как повторить

```bash
# 1. Поднять сервер на свободном порту теми же флагами, что и приложение
cd tools/gigastt
./gigastt serve --model-dir "$HOME/Library/Application Support/Meeting Recorder/gigastt-models" \
  --model-variant e2e_rnnt --port 9877 --pool-size 2 --max-session-secs 28800 \
  --hotwords-default --offline &

# 2. Эталон: офлайновый проход по тому же файлу
curl -s -X POST http://127.0.0.1:9877/v1/transcribe \
  -H "Content-Type: audio/wav" --data-binary @clip.wav > gold.json

# 3. Стриминг в реальном темпе куском N мс
swift tools/live-bench/bench.swift clip.wav 9877 2000 60 "порция 2 с"
```

Скармливать надо **стем** (`*.mic.wav` / `*.sys.wav`) — они уже 16 кГц моно, то
есть ровно то, что пойдёт в сессию из захвата.

Дальше WER считается против эталона на нормализованных словах (нижний регистр,
без пунктуации, `ё` → `е`).

## Что намерено 2026-08-06

Два клипа живой русской речи, 60 и 55 с:

| Порция | WER, клип 1 | WER, клип 2 | Слов на сегмент |
|---|---|---|---|
| 200 мс | 25.0 % | 33.6 % | 1.8 / 2.0 |
| 1000 мс | 23.6 % | — | 1.9 |
| 1500 мс | 13.9 % | — | 2.2 |
| **2000 мс** | **9.7 %** | **19.1 %** | 2.8 / 4.1 |
| 2500 мс | 12.5 % | — | 3.1 |
| 3000 мс | 13.9 % | — | 3.7 |

Оптимум на двух секундах, и он не монотонный: дальше сегменты крупнее, а
точность падает обратно. `--vad` не меняет ничего (те же 9.7 % при 2 с) и
ухудшает при 200 мс (29.2 %) — поэтому в приложении его нет.

Приложение шлёт **2 с** (`GigasttLiveSession.chunkFrames`). Плата — слова
появляются через ~2 с после того, как сказаны.
