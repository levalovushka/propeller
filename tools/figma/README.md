# Как узнать, какая это иконка в макете

В экспорте Figma иконки приезжают не именами, а глифами приватной области SF Pro
(`\u{1008CC}`, `\u{100757}` …). Имён в шрифте нет — глифы называются
`uni1008CC.medium`, — и таблицы «кодпойнт → имя» в системе тоже нет: проверено,
ни в `SF Symbols.app/Contents/Resources/Metadata/`, ни в
`CoreGlyphs.bundle/Contents/Resources/`.

Подбирать на глаз — то, чем один раз уже кончилось: три иконки из шести в разделе
настроек оказались другими (`bell.fill` вместо `bell.badge.fill`,
`archivebox.fill` вместо `opticaldiscdrive.fill`, незалитый граф вместо залитого),
и в строке они весили иначе, чем остальные.

`symmatch.swift` отвечает на это замером. Он рисует глиф по кодпойнту из SF Pro,
рисует каждый из 8302 символов `symbol_order.plist` по имени, нормализует оба
растра по bbox туши с сохранением пропорции и сравнивает попиксельно.

```bash
swiftc -O tools/figma/symmatch.swift -o /tmp/symmatch
/tmp/symmatch 1008CC 100757 100905
# U+1008CC: gearshape.fill (3684), play.diamond.fill (8746), …
```

Печатает четыре ближайших с расстоянием. **Верить можно, когда до второго места
разрыв в разы**: у `bell.badge.fill` он 7282 против 39417, у неоднозначных
(`bubble.fill` против `text.bubble.fill`) — единицы процентов, и тогда решает
глаз или контекст.

Кодпойнт берётся из `get_design_context`: он приходит прямо в тексте как
`{`\u{1008CC}`}`.
