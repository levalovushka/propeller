# Sparkle (авто-обновления)

Ключи EdDSA для подписи DMG в appcast.

| Файл | Куда |
|------|------|
| `eddsa_pub.txt` | **в git** — попадает в Info.plist как `SUPublicEDKey` |
| `private/eddsa_priv.key` | **НЕ в git** — Keychain (`--account propeller`) + локальный бэкап |

Feed URL по умолчанию:

`https://github.com/levalovushka/propeller/releases/latest/download/appcast.xml`

## Новый ключ (один раз)

```bash
SPARKLE_BIN=.build/artifacts/sparkle/Sparkle/bin
$SPARKLE_BIN/generate_keys --account propeller
$SPARKLE_BIN/generate_keys --account propeller -p > sparkle/eddsa_pub.txt
$SPARKLE_BIN/generate_keys --account propeller -x sparkle/private/eddsa_priv.key
```

## Релиз

```bash
./build.sh && ./notarize.sh && ./package-dmg.sh && ./make-appcast.sh
# Залей ВСЁ, что напечатал make-appcast: DMG + Propeller.dmg + appcast.xml + *.delta
# (он печатает готовую строку gh release upload)
```

`make-appcast.sh` кладёт в фид дельта-патчи к пяти предыдущим образам: полный DMG —
282 МБ, патч 1.16.6 → 1.16.7 — 1,0 МБ. Кто сидит на версии старше, чем есть патч,
качает полный образ, как раньше.

Перед печатью он применяет каждый патч к тому образу, который тот патчит, и сверяет
результат с приложением из этого релиза — файл за файлом (sha256, права, симлинки),
плюс `codesign` и `stapler`. Полный прогон ≈ 18 с. `VERIFY_DELTAS=0` выключает
проверку — только для отладки самого скрипта, не для релиза.

Три вещи, без которых релиз выйдет тихо неправильным:

- **`dist/` не чистить.** Патчи считаются из образов прошлых релизов, которые там
  лежат; пустой `dist/` — релиз без патчей, и это только предупреждение в одну
  строку, а не отказ. Пяти последних образов достаточно (`MAX_DELTAS`).
- **Заметки — `dist/RELEASE-<версия>-NOTES.md`, до запуска скрипта.** Он вкладывает
  этот файл в фид, и это то, что человек читает в окне обновления. Нет файла —
  окно пустое, скрипт скажет об этом последней строкой.
- **Релиз должен быть «latest», не черновик и не pre-release.** Фид живёт по
  `releases/latest/download/`, так что черновик выглядит опубликованным, а Sparkle
  продолжает отдавать прошлую версию. `make-appcast.sh` печатает готовые `curl`,
  чтобы это проверить после заливки.

Фид руками не правится: каждая строка подписана EdDSA по байтам файла. Любое
изменение — перезапуск скрипта.

## Критический релиз

```bash
CRITICAL_FOR=1.16.9 ./make-appcast.sh   # критично для всех ниже 1.16.9
CRITICAL_FOR=all    ./make-appcast.sh   # критично для всех
```

Без переменной релиз обычный. Сравнение строгое (`SPUAppcastItemStateResolver.m:94`),
поэтому называть надо **первую версию с фиксом**, а не сломанную.

Зачем: у Sparkle два интервала, и они про разное. Час (`SUScheduledCheckInterval`) —
как часто спрашиваем фид. Неделя (`SUScheduledImpatientCheckInterval`, дефолт 604800) —
сколько молчим про **уже скачанный** патч, прежде чем показать окно. Как только патч на
диске, следующий цикл — `MAX(час, неделя)` для обычного релиза и `MIN(час, неделя)` для
критического (`SPUUpdater.m:527-535`). На установку не влияет: она всё равно при
следующем выходе из приложения.

Полный порядок шагов и почему он такой — `CHANGELOG.md`, раздел «Как готовить релиз».
