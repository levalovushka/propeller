## Что это

Нативное macOS-приложение (**Propeller**, SwiftUI, menu bar + окно, macOS 14.4+, Apple Silicon): записывает встречи (микрофон + системный звук на общих часах), локально транскрибирует русскую речь через **GigaAM-v3 / gigastt** — живьём во время встречи и офлайном в архив, — диаризует спикеров через **FluidAudio**, сохраняет markdown (Simple по умолчанию / Obsidian опционально) и генерирует LLM-саммари, которое можно править на месте.

**ASR и диаризация — на устройстве.** Саммари может обращаться к локальной Ollama или (если пользователь задал ключ) к облачному API. Никакой контент встречи (аудио/транскрипт/саммари) не уходит в облако сам по себе.

**Целевой сценарий:** «установил, настроил и забыл». Аудитория — менеджеры; в приложение заходят в основном чтобы забрать готовое саммари.

## Ключевые концепции

### Запись (Recording)

Аудиозапись со своим транскриптом. Живут списком в sidebar. У каждой:
- Заголовок (авто из саммари, если саммари включено; иначе «Recording <дата>»; редактируемый — ручное переименование латчится и не перезаписывается авто-заголовком)
- Дата/время, длительность, размер аудио (если файл ещё на месте)
- Стадия (`RecordingStage`): `recording` / `recorded` / `transcribing` / `transcribed_raw` / `transcribed` / `saved` / `summarized`.
  `summarized` = есть и конспект, и метаданные; сверяется с диском при загрузке.
- Транскрипт (текст с лейблами спикеров и таймстемпами)
- Заметки (свободный текст + быстрые заметки с таймкодами)
- Производные от саммари: **темы** (сабтайтл через запятую) и **теги** (из утверждённого словаря)

Аудио можно удалить отдельно от транскрипта, чтобы освободить место.

### Спикеры

**Никакой библиотеки голосов и voice-matching.** Диаризация FluidAudio даёт **консистентные `Speaker 1/2/3` в пределах звонка** — «тупо и надёжно» (plan-v2 Job 3). Поверх этого пола — два дешёвых сигнала именования:

- **Владелец = микрофонный стем.** Кластер, доминирующий в mic-стеме (относительно системного), детерминированно подписывается именем пользователя из онбординга (`TranscriptionService.resolveOwnerName`). Даёт самое ценное имя — своё — бесплатно.
- **(план 4.7) Имена из текста на этапе саммари** — LLM сопоставляет `Speaker N` ↔ имя по обращениям/представлениям + ростер из календаря, только при уверенности. _Отложено вместе с Джобой 4._

**Ручное переименование** — на уровне спикера: из панели участников имя применяется сразу ко всем репликам этого `Speaker N` одним действием (`AppState.reassignSegments`); точечная правка отдельной реплики — через контекстное меню сегмента. Правка чисто текстовая: без профилей и обучения.

### Календарь (Upcoming)

Read-only чтение системного Календаря macOS через **EventKit** (Google/Exchange-аккаунты подхватываются, если заведены в «Учётные записи»). **Без OAuth и без облака** — только разрешение, как на микрофон. Календарь **называет записи** (`suggestedRecordingTitle`, `CalendarMeta`) и больше ничего не рисует: секция «Скоро» и пер-строчные действия удалены 2026-08-04 вместе с прежним экраном списка — рельс и есть список.

## Пайплайн и поток данных

```
MeetingDetector (Auto: Zoom, Контур.Толк) / menu bar / ⌘R / кнопка
  → AudioRecorder → ProcessTapCapture  mic (.mic.wav) + system (.sys.wav) одной IOProc → офлайн-микс {id}.wav
      ↳ те же кадры → LiveTranscriptService → живой транскрипт на экране записи
  → TranscriptionService
      → gigastt ASR (ASRSegment[])
      → checkpoint status=transcribed_raw     (чтобы краш на диаризации не потерял дорогой ASR)
      → FluidAudio диаризация → Speaker N + владелец-по-микрофону
  → MarkdownWriter (simple | obsidian)         → save (транскрипт всегда сохраняется)
  → RecapService (если провайдер доступен)     → recap.md
      → generateMetadata → заголовок / темы / теги
```

Транскрипт **всегда** сохраняется сразу после диаризации — без ручного шага подтверждения спикеров.

### Крэш-рекавери (при старте)

- `recording` + существующее аудио → `recorded` (длительность из WAV-заголовка)
- `transcribing` с транскриптом → `transcribed_raw` (возобновить только диаризацию, не гоняя ASR заново); иначе → `recorded`

## Саммари (рекап)

Слой поверх сохранённого транскрипта. Провайдер: **Ollama** (дефолт) / OpenAI / Claude. **Выключателя нет** (2026-08-07): саммари — то, зачем приложение существует, и «Выкл» отключал именно это. **«Авто» тоже нет** (2026-08-07): оно означало «Ollama, а если её нет — тот облачный, у кого нашёлся ключ», то есть настройку, по которой нельзя сказать, куда уедет транскрипт. Сохранённые `off` и `auto` переезжают на `ollama` при чтении (`Preferences.recapProvider`). Локальная модель по умолчанию — `qwen3.5:4b` (~3,4 ГБ; переезд с `qwen2.5:7b` 2026-07-27 — качество на реальных транскриптах не хуже при вдвое меньших весах). Reasoning-модели зовём с `think: false`: иначе рассуждения съедают окно и `content` приходит пустым. Ключи — в Keychain. Модель выгружается через `keep_alive: 90` + `OllamaSidecar.stopAfterIdle`.

- **Промпт** (дефолт 2026-07-27) — конспект договорённостей, не стенограмма. Структура Markdown (`##`, никогда `#`): **Итог** → **Решения** → **Задачи** (`**Кто** — что — **срок**`) → **Открытые вопросы** → **Ход обсуждения** (темы с таймкодами) → **Прочее**. Пустые секции опускаются. Заметки пользователя вплетаются по смыслу; сырой блок «Заметки» дописывает система. К любому промпту всегда append `languageLock` (только русский). Настраивается в настройках → «Нейросети» («Сбросить промпт» возвращает дефолт).
- **Редактируемое саммари** — Edit/Done прямо в приложении, правка пишется в `recap.md`.
- **Метадата из саммари** (отдельный structured-JSON вызов): заголовок (3–7 слов, если не задан вручную и не взят из календаря), темы (2–5), теги из словаря.
- **Заголовок при старте записи:** приоритет у пересекающегося/скорого события календаря (`CalendarService.suggestedRecordingTitle`); иначе placeholder «Recording …»; LLM переименовывает только авто-placeholder.
- **Словарь тегов v1 (13):** `1:1`, `стендап`, `ретро`, `планирование`, `дизайн-синк`, `дискавери`, `брейншторм`, `стратегия`, `клиентская`, `защита решения`, `найм`, `админ`, `внутренняя`. Значения вне словаря отбрасываются.
- **Backfill:** саммари для записей без него догенерируются молча в фоне, когда провайдер доступен — без кнопки; не запускается во время звонка/записи/транскрипции.
- Если провайдера нет — саммари тихо пропускается с подсказкой в UI; встреча всё равно открывается (транскрипт + заметки видны).

## Заметки

- **Во время записи (окно):** та же колонка заметок, что у готовой встречи (`MeetingNotesColumn`), запись идёт в `noteItems` через `RecordingStore.appendNote`.
- **Заметка в чёлке** (только во время записи): ⌃⌥N или клик по правому уху опускают вырез в поле ввода — вниз, вширь чёлка не расходится; значок в ухе при этом сменяется с карандаша на ⏎. Видно три строки 13/16 (раскрытая чёлка 14″ — 96 pt), набор идёт по нижней: написанное раньше поднимается и гаснет под градиентом, а не обрезается кромкой. Enter и клик по ⏎ делают одно и то же — сохраняют; Esc и повторный ⌃⌥N выходят без сохранения. Enter сохраняет заметку **с таймкодом**, Esc выходит без сохранения. Подтверждение — то, что поле закрылось, и больше ничего. Глобальный хоткей требует Accessibility/Input Monitoring. Поле стоит у камеры намеренно: печатая в него, человек на встрече продолжает смотреть в объектив, а не вниз.
- **Без выреза фичи нет вовсе** — ни плиты, ни ⌃⌥N. Air M1, iMac, ноутбук с закрытой крышкой на внешнем мониторе: заметки там пишутся в колонке окна, индикации записи в чёлке нет. Второе важнее первого: горячая клавиша, открывающая невидимое поле, — это клавиатура, проваливающаяся в никуда посреди встречи. Вырез может появиться и исчезнуть по ходу записи (крышку открыли, монитор отключили, переключили разрешение) — плита поднимается и уходит вслед за ним.
- В саммари заметки **вплетаются в конспект по смыслу**; дословно система дописывает отдельный блок «Заметки» в файл — LLM их не переписывает отдельной секцией.

## Поиск (⌘K)

Полнотекст по транскриптам + заметкам (план 6.2 — добавить в индекс саммари). Фильтр-чипы. Теги в поиск не входят (для них — фильтр в списке, план 6.3).

## Страницы / вью

### Рельс (`PropellerSidebar`)
Одна колонка 300 pt: заголовок окна со светофором, меню, встречи по дням. Секций
«Библиотека» / «Summaries» / «Скоро» нет — рельс и есть список; отдельного экрана
саммари нет, потому что саммари и есть встреча. Какой вид получает строка, решает
`SidebarRowMachine` в `PropellerPure` — единственное место, где это решается.

У подошвы, пока есть неотвеченный вопрос, стоит блок настройки (имя, календарь;
`SetupPromptMachine`); список под ним гасится градиентной маской, а не
закрывается плитой. ПКМ по строке — системное меню: копировать саммари,
поделиться, показать в Finder, удалить аудио, удалить встречу.

### Панель встречи (`MeetingPane`)
Заголовочный блок (дата, редактируемый заголовок, темы) + две колонки: саммари и
заметки. Заметки свёрнуты по умолчанию; их раскрытие раздвигает окно, если места
не хватает (`WindowReveal`), а не сжимает саммари в щель.

Колонка саммари показывает **самое глубокое из готового** (`SummaryColumnContent`):
саммари, если оно есть; иначе расшифровку, пока саммари ещё будет; и только когда
дальше ничего не будет — строку о том, почему. Готовое саммари проявляется
печатью и **правится на месте**: щелчок ставит каретку, выделение поднимает
панель действий (вид блока, жирное, курсив, «Короче» / «Подробнее»). Статус-pills
и плеер с волновой формой удалены вместе с прежней карточкой.

### Идущая запись (`RecordingPaneView`)
Не режим окна, а одна из встреч: панель показывает её, только когда она же и
выбрана. Шапка — заголовок слева, таймер и две кнопки справа (пауза, стоп). Слева
живой транскрипт (владелец / «Собеседник»), справа те же заметки, что у готовой
встречи. ⌘. останавливает запись из любого места; удаление строки записываемой
встречи означает «не записывать её».

**Без наушников каждая реплика собеседника видна один раз.** Микрофон слышит её из
колонок, и живой слой распознаёт её дважды — но реплика, которую собеседник уже
сказал, под именем владельца не показывается (`EchoDedup`). Своя речь поверх чужой
при этом остаётся: она может задержаться на секунду с половиной, пока не станет
видно, что это не эхо, а в тишине не задерживается вовсе.

### Menu bar
Упрощён до быстрых действий: primary (запись/стоп + таймер при записи), Recent, Open/Settings/Quit. Без информеров.

## Настройки (состояние правой панели)

**Окна настроек нет** (2026-08-07). Настройки — такое же состояние контентной
панели, как открытая встреча: строка «Настройки» в рельсе, ⌘, и пункт меню-бара
показывают окно и переключают панель (`AppState.paneRoute`, `SettingsOpener`).
Ширина колонки — саммарийная (те же поля, тот же потолок 640 pt). Вместо пяти
вкладок — один столбец групп; вёрстка в `PropellerUI/SettingsKit.swift`,
содержимое в `Sources/SettingsPane.swift`. Интерфейс русский целиком (2026-07-25).

- **Основное** — запуск при логине (`SMAppService`); автоматическая запись (тумблер, дефолт вкл; старт без диалога, отмена системным уведомлением «Не записывать»; на диске по-прежнему `AutoRecordMode` off/auto); иконка в строке меню (тумблер, дефолт вкл — `MenuBarExtra(isInserted:)`; из поповера доступно только «Скрыть из меню-бара», вернуть — отсюда).
- **Аналитика** — анонимная телеметрия (тумблер).
- **Нейросети** — **словарь** hotwords, реально прокинутый в gigastt (`--hotwords-file` + `--hotwords-default`, рестарт sidecar по изменению); модель для саммари (**Ollama / OpenAI / Claude**, дефолт Ollama) — состояние локального движка второй строкой (включая процент загрузки), у облачных провайдеров **только у выбранного** показываются ключ и модель, у Ollama настраивать нечего: имя модели приложение выбирает и привозит само; промпт.
- **Хранилище** — формат Simple / Obsidian; пути; «Аудио на диске» + «Очистить».
- **О программе** — версия и «Проверить обновления…» (Sparkle).

Показаний прибора в настройках нет: ушли «Движок расшифровки» (он ровно один), строка «Состояние» с ручной пробой детектора и кнопка «Проверить» у Ollama — настройка это то, что человек меняет. Строки «Показывать встречи из Календаря» тоже нет: секция «Скоро» удалена 2026-08-04, календарь только **называет** записи, а включается блоком у подошвы рельса.

Раздела **«Аудио» нет**: он предлагал выключить захват системного звука, то есть
вторую сторону разговора. Запись без неё — половина реплик и саммари по половине
встречи, поэтому это не настройка (`Preferences.captureSystemAudio` всегда `true`;
записанное `false` больше не читается). Отдельного разрешения захват не требует —
дальняя сторона идёт из тапа Core Audio. Опция voice-processing / AEC удалена
2026-07-28 — Apple VPIO перенастраивает общее входное устройство и портит саму встречу.

```
  meetings/     {id}-{slug}.md, {id}-{slug}-recap.md

  hotwords.txt      # словарь Domain terms для gigastt

```

## Форматы вывода

- **Simple** (дефолт) — читаемый `.md`: заголовок, дата/длительность/участники, тело, блок «Заметки». Без YAML/wikilinks — для коллег без Obsidian.
- **Obsidian** — YAML frontmatter + `tags: [meeting, recap]`.
- **Copy for chat** — саммари/транскрипт в буфер обмена (основной канал шеринга v2).

## Ключевые принципы

1. **Локальность.** ASR и диаризация на устройстве; облако — только опциональный recap-API и read-only календарь.
2. **Install & forget.** Автозапись звонка (Zoom / Контур.Толк) → авто-транскрипт → всегда save → авто-саммари; отмена — уведомлением.
3. **Тупо и надёжно про спикеров.** Консистентные `Speaker N` — надёжный пол; имя владельца бесплатно с микрофона; никакой хрупкой voice-library.
4. **Транскрипт — сырьё, саммари — продукт.** Инвестиции в редактирование саммари, а не транскрипта.
5. **Русские встречи.** GigaAM — только ru.

## Надёжность и энергоэффективность

Инженерный слой (ленивый ASR-sidecar, timer coalescing, поллинг звонков, Core Audio taps, тесты) вынесен в отдельный трек — см. [`../../plan-optimization.md`](../../archive/plan-optimization.md).

## Технологии

SwiftUI (macOS 14.4+) · Swift Package Manager · **gigastt / GigaAM-v3** (HTTP sidecar + WS для живого слоя) · **FluidAudio** (диаризация) · Core Audio process taps / AVFoundation · Metal (шиммер, распад) · EventKit (календарь) · UNUserNotifications · Ollama (движок в бандле) / OpenAI / Claude (recap).
