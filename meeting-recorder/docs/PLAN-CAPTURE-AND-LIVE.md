# План: общие часы, раздельные потоки, живой транскрипт

_Составлен 2026-07-29. Заменяет связку «SCK-стем + сайдкар gigastt» на «process tap
+ агрегатное устройство + FluidAudio». Основание — замеры этого дня
([ECHO_AND_MIX_EXPERIMENTS.md](ECHO_AND_MIX_EXPERIMENTS.md),
[AUDIO-CAPTURE-CASES.md](AUDIO-CAPTURE-CASES.md)) и разбор архитектуры talat._

## Зачем менять то, что работает

Сегодняшний захват честно пишет обе стороны, но у него три врождённых свойства,
которые нельзя вылечить по отдельности:

1. **Дорожки не на одних часах.** Микрофон пишет `AVAudioRecorder`, системный звук —
   ScreenCaptureKit. Отсюда сдвиг старта (замерено 200–484 мс, приходится измерять
   и хранить) и дрожание в единицы миллисекунд, из-за которого когерентность
   дорожек **0.04** — эхоподавитель на них не сходится в принципе.
2. **Микрофон — чёрный ящик.** `AVAudioRecorder` отдаёт файл и ничего больше: ни
   буферов, ни таймстемпов. Живой транскрипт из него не сделать.
3. **ASR живёт в сайдкаре.** Отдельный бинарь, HTTP, лимит тела запроса, клиентский
   чанкинг — и весь класс отказов вокруг (HTTP 413 на встречах длиннее 25 минут
   стоил нам релиза 1.13).

Process tap + агрегатное устройство закрывают первые два **по построению**: обе
дорожки снимаются одним устройством, сэмпл в сэмпл, и приходят буферами. Переход на
FluidAudio закрывает третий и попутно даёт стриминг.

## Что уже есть в дереве (сверено 2026-07-29)

`FluidAudio` мы линкуем ради диаризации, и в нём же лежит:

| Что | Где | Замечание |
|---|---|---|
| **Parakeet TDT 0.6b v3**, мультиязычный | `AsrModels.downloadAndLoad(version: .v3)` — это дефолт | Та самая «третья» модель |
| Скользящее окно для стриминга | `SlidingWindowAsrSession` | Сессия держит модели один раз и раздаёт потокам |
| Два источника из коробки | `AudioSource.microphone` / `.system` | Ровно наш случай |
| Семантика живого текста | `confirmedTranscript` + volatile | Подтверждённое не переписывается |
| VAD со стримингом | `VadManager+Streaming` | silero |
| Диаризация | уже используем | pyannote + wespeaker |
| Рескоринг словаря при подтверждении | в стриминге | Сюда переезжают наши хотворды |

Строить самим остаётся: **захват** (tap + агрегат), склейку двух потоков в один
транскрипт, миграцию словаря и AEC, если решим, что он нужен для слуха.

Минимум macOS: у пакета 14, у process taps — 14.4, у talat в проде 15. Наш текущий
минимум 14.0 придётся поднять.

## Гейт: русский на Parakeet v3

**Начинаем не с кода, а с замера** — решение владельца: берём v3, если качество
русского приемлемо.

Метод: три окна по пять минут из реальных встреч (у нас есть записи со стемами).
Одно вычитывается руками как эталон → считаем WER для GigaAM и для v3. Остальные два
читаем глазами на предмет терминов из словаря, имён и чисел.

Критерий приёмки: **v3 не хуже GigaAM больше чем на 2 п.п. WER** и не теряет
доменные термины систематически.

Если v3 хуже: план не отменяется, но финальный проход остаётся на GigaAM, а v3 идёт
только в лайв. Это дороже (два движка), поэтому развилка честно фиксируется здесь.

## Этапы

Каждый этап отгружаем отдельно и он ценен сам по себе.

### Э1. Замер качества (гейт)

Без изменений в проде. Результат — таблица WER и решение по развилке выше.

### Э2. Захват на общих часах

`AudioHardwareCreateProcessTap` на процесс(ы) платформы, чей звонок идёт, +
`AudioHardwareCreateAggregateDevice`, включающее тап и микрофон. Обе дорожки — из
одного устройства, одним колбэком.

Закрывает: **M2** (сдвиг старта исчезает как понятие), **M6** (дрожание),
частично **M3** (агрегат переживает смену устройства лучше, но проверить отдельно).
`StemTimeline`, `systemStemOffset` и вся арифметика сдвига удаляются.

Проверка приёмки: когерентность дорожек в речевой полосе **> 0.7** (сегодня 0.04) —
меряется скриптом из `tools/echo-probe/`.

Риск: tap живёт на macOS 14.4+, у нас в поле есть 14.x — поднимаем минимум и пишем
это в заметках релиза. Второй риск: захват «всей машины» тоже надо уметь тапом
(процесс не один) — либо оставляем для этого случая SCK, либо тапаем дефолтный
выход.

### Э3. Раздельная транскрипция офлайн

Два стема — два прохода FluidAudio, склейка по таймкодам. Эхо из микрофонного потока
отбрасывается сравнением с системным (совпало по времени и по тексту — это эхо).
Владелец определяется структурно, а не сравнением энергий, — эвристика
`resolveOwnerName` уходит.

Выпиливается: `gigastt` (бинарь ~250 МБ + модели), `GigasttSidecar`,
`GigasttClient`, `GigasttChunking`, обвязка вокруг 413 и таймаутов.

Проверка приёмки: на тех же окнах, что мерили сегодня, «речь дальней стороны
доходит» ≥ 95 %, уверенность не ниже GigaAM.

### Э4. Живой транскрипт

`SlidingWindowAsrSession` на два источника, `confirmed` + volatile в UI. Живой текст
идёт с микрофона и системного потока раздельно, то есть «кто говорит» видно сразу.

Здесь же пересматривается модель состояний: пользовательских состояний конвейера
становится четыре (идёт запись → обрабатываем → готово → ошибка) вместо
одиннадцати, как мы и обсуждали в редизайне.

Проверка приёмки: задержка появления строки, RTF под нагрузкой реального звонка,
отсутствие переписывания уже подтверждённого текста.

### Э5. AEC — только ради слуха

После Э2 когерентность высокая, значит AEC3 (Rust-крейт или C++ `webrtc-audio-processing`)
наконец сходится. Нужен он **не для транскрипта** — раздельные потоки его уже
решают, — а чтобы запись было не противно слушать.

Проверка приёмки: ERLE > 12 dB на реальной записи без наушников, речь владельца при
перебивании не пропадает.

### Э6. Уборка

Словарь хотвордов → vocabulary rescoring FluidAudio. Фикстуры границ (413, «модель
ушла в thinking») теряют смысл — заменяются фикстурами нового движка. Документы,
галерея состояний, `STATE.md`.

## Что ломается в контрактах

| Контракт | Что с ним |
|---|---|
| `Transcriber` (граница) | Интерфейс остаётся, реализация меняется целиком; фикстуры границ переписываются |
| `RecordingStage` | Значения не меняются, но при лайве `transcribed_raw` достигается **до** остановки записи — правила очереди пересмотреть |
| `RecordingEntry.systemStemOffset` | Перестаёт быть нужным; поле оставить читаемым ради старых записей |
| Стемы на диске | Остаются: `.mic.wav` / `.sys.wav`, только теперь синхронные |
| Дистрибуция | GigaAM 247 МБ в бандле → Parakeet v3 (~2 ГБ) качается. Офлайн «из коробки» теряется, если не бандлить. **Развилка**: качать в онбординге, как модель саммари, или собирать тяжёлый DMG |
| Лицензии | Проверить до шипа: parakeet-tdt-0.6b-v3 (NVIDIA) и конверсию FluidInference |

## Риски

| Риск | Чем закрываем |
|---|---|
| Русский у v3 хуже GigaAM | Гейт Э1; запасной путь — v3 только в лайве |
| Tap не отдаёт звук браузера / незнакомого приложения | Для «всей машины» остаётся отдельный путь; браузер и так вне области |
| macOS 14.0 у кого-то в поле | Поднять минимум до 14.4, сказать в заметках; на 14.0 остаётся старый билд |
| Размер моделей | Решение по дистрибуции принимаем в Э3, не позже |
| Регресс качества на живых встречах | Каждый этап — с замером на тех же окнах; метрики уже отработаны сегодня |

## Порядок и объём

Э1 — часы. Э2 — самый рискованный и самый ценный, дни. Э3 — дни, зато удаляет
больше, чем добавляет. Э4 — дни. Э5 — опционально. Э6 — по ходу.

Порядок жёсткий: Э1 → Э2 → Э3 → Э4. AEC и уборка вставляются где удобно, но не
раньше Э2.
