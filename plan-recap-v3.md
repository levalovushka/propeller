# План — конспект v3: «поиск → проверка → вёрстка»

_Создан 2026-08-14. Раздаётся сессиям пакетами; каждый пакет — бриф одной сессии.
Основание — разбор той же даты: контур «свободное порождение → починка» упёрся
в структурный потолок (пространство дефектов свободного текста бесконечно,
детекторы перечислимы; суды находят новый класс дефектов каждым заходом —
`tools/recap-lab/OPTIMIZATION.md`, A5.2 и JUDGE-1..3)._

## Идея одним абзацем

Модель перестаёт быть писателем и становится искателем. Извлечение идёт окнами
по транскрипту в **JSON по схеме** (constrained decoding): каждое утверждение
несёт дословную цитату-спан, таймкод и исполнителя **из закрытого списка имён
встречи**. Проверка — мелкими бинарными вызовами по паре (утверждение, цитата),
а не регекспами. Вёрстка секций — код без генерации; проза — только «Ход
обсуждения», по одному короткому абзацу на тему из утверждений этой темы.
Дефекты, которые сегодня чинятся фильтрами, становятся непорождаемыми:
выдуманное имя не проходит enum, эхо промпта не влезает в схему, парсер меток
не нужен, двойной пересказ невозможен по построению.

## Контракт утверждения (общий для всех пакетов, менять только решением владельца)

```json
{
  "type": "agreement | task | question",
  "text": "формулировка пункта, по-русски",
  "quote": "дословный спан из окна транскрипта",
  "t": "MM:SS — ближайший таймкод не позже начала спана",
  "owner": "имя из закрытого списка или null",
  "deadline": "строка срока или null"
}
```

Правила контракта:
- `quote` обязан быть подстрокой окна (проверка кодом; допуск — нормализация
  пробелов). Не подстрока → утверждение отбрасывается, счётчик отбросов в stats.
- `owner` — enum: имена из шапки встречи + календарных участников + словаря имён
  транскрипта. Не уверена → `null`. «Без исполнителя» — честное состояние, а не дефект.
- `deadline` без прозвучавшего срока — `null` (правило из EXTRACT_PROMPT действует).

## Пакеты

### П0 · Нулевая проба — фальсификация парадигмы

**Одна сессия, только стенд, ноль Swift. Всё остальное существует, только если П0 зелёный.**

Вход: `tools/recap-lab/` (промпт-инфраструктура `promptlib.py`, нарезка по
репликам `chunked.py`, счёт `golden_match.py`, ансамбль для ABAB-пары
`bench_ensemble.py`), golden обеих встреч.

Шаги:
1. Проверить, что локальная Ollama умеет structured outputs (`format` =
   JSON-схема в `/api/generate`; нужна ≥0.5). Не умеет → обновить и записать
   версию в stats; версия — часть условий воспроизводимости.
2. `bench_extract.py`: нарезка на окна ~13k символов по границам реплик
   (переиспользовать резку `chunked.py`; 13k — проверенная точка A1/chunk-facts)
   с перекрытием ~20%; два прохода на окно — t=0 и t=0,7; JSON по контракту;
   объединение; дедуп только точный/почти-точный (по принципу дубля).
3. Спан- и enum-проверки кодом; отброшенные — считать, не прятать.
4. Счёт `golden_match.py` на обеих golden-встречах, **чередованно с ансамблем в
   одной сессии** (ABAB, n≥5 на ячейку, ретрай схлопнувшихся, reply_tokens в таблице).
5. Контроль формы: если покрытие просело — та же нарезка со старым свободным
   EXTRACT_PROMPT (это существующие числа facts.md: среднее 8,3, максимум 11),
   чтобы отделить «схема душит модель» от «окна не работают».

**Критерий (записан до прогонов):**
- покрытие пулом по двум встречам ≥ ансамбля − 1,0 **и** ≥ базы + 2,0
  (ориентиры своих батчей: ансамбль 11,4 и 13,8, база 8,2 и 11,2 — но сравнение
  только внутри своего ABAB);
- доля отброшенных спан-проверкой ≤ 15% утверждений;
- 0 находок всех четырёх детекторов `check_defects.py` на отрендеренном списке;
- wall-time и пик RAM записаны (информационно, не гейт; окна малы — ожидание,
  что путь один и для 8 ГБ, проверить именно это).

**Стоп-условие:** покрытие ниже базы → парадигма отвергнута, план закрывается,
пауза с 1.17 снимается. Провал только по схеме (шаг 5 показывает, что свободные
окна работают, а JSON нет) → один заход на упрощение схемы (меньше полей),
второго не давать.

### П1 · Верификатор утверждений

**Одна сессия. После П0. Параллельно с П2 и П3.**

Идея: заменить owners.py/θ/стемы одним механизмом — бинарный вызов по паре
(утверждение, цитата + окно вокруг неё): «подтверждает ли цитата (а) действие,
(б) исполнителя, (в) срок?» → `{action: bool, owner: bool, deadline: bool}`.
4B надёжна на ~30 строках — записано на доске (A5, «что дальше по ветке»).

Шаги:
1. Собрать размеченный сет из вердиктов судов (`judge/JUDGE-2.md`, `JUDGE-3.md`,
   `verdicts*`): известные ошибки — «Саболь» в слоте (11 задач из 22 на m2),
   перестановка сроков (4 из 5 m2-ячеек), кентавр «Саша Шукурова» в прозе
   (5 ячеек m3) — плюс подтверждённо честные пары оттуда же. Цель — 60–100 пар.
2. Промпт верификатора + харнесс, t=0.
3. Замер: precision/recall на сете.

**Критерий:** ловит ≥ 80% размеченных ошибок атрибуции и срока; убивает ≤ 10%
честных. Вокативы не ловятся базовым промптом → один заход с явным
вокатив-вопросом в промпте («это обращение к человеку или назначение ему?»).

**Стоп-условие:** после двух вариантов промпта recall < 60% или убийство честных
> 20% → верификатор не тянет, на доску честно; v3 живёт без него (спан + enum
уже закрывают худшее), но «Саболь»/сроки остаются známыми дырами — решение
владельца в П4.

### П2 · Карта тем и проза по темам

**Одна сессия. После П0. Параллельно с П1 и П3.**

1. Проход-карта: агенда встречи по таймкодам (короткий вызов; окна уже есть).
   Фолбэк — механическая сегментация по паузам/сменам состава говорящих.
2. Абзац на тему: вход — только утверждения и цитаты этой темы, выход — 2–4
   предложения. Имена в абзаце — только из enum (проверка кодом). Одна нить —
   по построению.

**Критерий (локальный, до суда):** 0 имён вне enum; длина абзаца в границах;
темы покрывают ≥ 90% таймлайна без пересечений. Читаемость меряет только суд П4
(планка судьи из JUDGE-3: ≥ 3,4; база 3,25).

### П3 · Рендер и инварианты

**Одна сессия. Стартует после П0 по контракту (фикстуры), финал — после П1/П2.
Механика — можно отдать Sonnet-сессии.**

1. `render_v3.py`: секции из проверенных утверждений, хронологически; бюджет
   ≤ 14 буллетов жадным отбором (внутри бюджета новое предпочтительнее повтора —
   граница принципа дубля); «Ход обсуждения» — абзацы П2; notes пользователя —
   в документ, не в ветки (правило 1.17 наследуется).
2. `invariants.py`: (а) спан каждого пункта есть в транскрипте, (б) исполнитель
   в списке участников, (в) срок — внутри своего спана. Работает на **любой**
   встрече без калибровки — это и будущая прод-телеметрия, и замена
   якорей-на-каждую-встречу для грубой оценки.
3. Фикстуры в духе `test_parse.py`: контракт → документ, включая пустую встречу
   (честный отказ), утверждения без owner, дубль с двумя таймкодами.

**Критерий:** фикстуры зелёные; рендер — неподвижная точка (повторный рендер
байт-в-байт); `invariants.py` на существующих старых конспектах не падает
(им — только отчёт, их не чиним и не перегенерируем).

### П4 · Сквозной прогон и независимый суд

**Две сессии: прогон и суд — разные. После П1+П2+П3.**

1. Прогон: полный конвейер на трёх встречах гейта №2, ABAB против базы, n≥5;
   против старого ансамбля — хотя бы на одной встрече (дорого, но это цена
   вердикта). Вся методика доски действует, включая приёмку стратума.
2. Суд: слепой, по протоколу `judge/` (`blind.py`, mapping), **сессией, которая
   ничего в v3 не строила**. Оси: читаемость, атрибуция, полнота, выдумки.

**Критерий (записан до прогонов):** покрытие пулом ≥ ансамбля − 1,0 и ≥ базы
+ 2,0 при p < 5%; выдумки ≤ базы; буллетов ≤ 14; суд: читаемость ≥ 3,4,
неверные исполнители ≤ 37% (обе планки — цели из JUDGE-3).

### П5 · Решение и порт
