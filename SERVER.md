## 2. Что запущено

| сервис | как | конфиг |
|---|---|---|
| Caddy v2.11.4 | systemd `caddy`, слушает 80/443, TLS от Let's Encrypt автоматически | `/etc/caddy/Caddyfile` |
| Сайт | статика с диска | `/var/www/site` (владелец `deploy:deploy`); лендинг из `site/` этого репо |
| Сервис шеринга | systemd `propeller-share`, слушает `127.0.0.1:8080`, Caddy проксирует на него `/s/*` и `/api/*` | `/etc/systemd/system/propeller-share.service`, секрет в `/etc/propeller-share.env` |

Caddyfile: `propeller.report` → статика; `/s/*` — заголовки
`X-Robots-Tag: noindex, nofollow` и `Cache-Control: private, no-store`, прокси
на :8080; `/api/*` — прокси на :8080; `www.` → 308 на голый домен. Общие
заголовки: `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`.
`robots.txt`: `Disallow: /s/`.

DNS (заведено 2026-08-24): A `@`/`www` → 201.24.53.31, AAAA `@` →
2a03:6f00:a::2:f155, NS Timeweb. Сертификат Let's Encrypt выпущен, продление
автоматическое (лог: `journalctl -u caddy`).

Деплой сайта — автоматический: push в `main`, трогающий `site/**`, запускает
`.github/workflows/deploy-site.yml` → rsync в `/var/www/site` от пользователя
`deploy` (вход только по CI-ключу; приватная часть — лишь в секрете
`DEPLOY_SSH_KEY` репо, host key сервера прибит в workflow). Руками:
`gh workflow run deploy-site.yml`. `site/robots.txt` обязан жить в репо —
деплой идёт с `--delete`, файлы мимо `site/` затираются. Netlify
(propellerapp.netlify.app) остаётся запасным. Git этого репо ходит в GitHub от
`levalovushka` (локальный `credential.helper` → gh; аккаунт llleva — не для
Propeller).

## 3. Механика шера — контракт (решение владельца 2026-08-24, правки 2026-08-27)

Ключевой принцип: **сервер не видит содержимого саммари** (E2E). Приватность
держится на конструкции, а не на обещаниях.

1. Приложение собирает саммари в JSON-документ (имя, строка атрибутов, блоки),
   сжимает сырым DEFLATE, генерирует ключ K (32 байта), шифрует AES-256-GCM.
   **Не готовый HTML**, как предполагала спека 2026-08-24: вьюер один на все
   шеры, и пока он рисует разобранный документ, страницу можно переодеть под
   новый дизайн, не переиздавая уже разосланные ссылки.
2. `POST /api/shares?ttl=week|month` (Bearer-ключ приложения; лежит в `Info.plist` сборки, куда его кладёт `build.sh` из `swift/.share-secret` — **решение владельца 2026-08-27**: в Keychain он был бы только у автора, и у всех остальных «Поделиться» не работало бы вовсе):
   блоб → сервер возвращает id = 16 случайных байт, base64url, 22 символа
   (перебор 2^128 — невозможен; плюс rate-limit на GET) и токен отзыва,
   от которого на сервере хранится только SHA-256.
   **«Вечной» ссылки нет** (решение владельца 2026-08-27): бэкапов у машины
   нет осознанно, и срок, обещающий её пережить, был бы враньём.
3. Ссылка: `https://propeller.report/s/<id>#<slug>&k=<base64url K>` — фрагмент
   после `#` браузер на сервер не отправляет. Там живут обе вещи, которых
   сервер видеть не должен: ключ и **название встречи** латиницей
   (`vstrecha-s-daney`). Слаг в пути был бы красивее и так и просили
   2026-08-27 — отменено в тот же день: путь сервер получает всегда, а имя
   встречи это содержание.
4. Открытие: сервер отдаёт статичный вьюер, JS берёт ключ из `location.hash`,
   скачивает блоб, расшифровывает (WebCrypto + `DecompressionStream`),
   показывает. Без JS страница не откроется — осознанный компромисс в пользу
   E2E. Вместе с блобом уезжает заголовок `X-Share-Expires`: страница говорит
   читателю, когда ссылка исчезнет, — она временная, и узнать об этом лучше до
   того, как её положат в закладки. Нового знания это не даёт (спросить можно
   только по id, а 200 и без того означает «шер существует») и стоит только
   на удачном чтении, не на 404.
5. Отзыв: `DELETE /api/shares/<id>` с заголовком `X-Share-Token`. Просроченное
   подметает сам сервис раз в час.
6. Несуществующая = просроченная = отозванная = отзыв чужим токеном:
   **одинаковый пустой 404** (нет оракула существования). Страница `/s/<id>`
   при этом отдаётся под любым правильным id — иначе её код ответа стал бы тем
   же оракулом. Листинга шеров на сервере нет: список живёт только в
   приложении (`~/Library/Application Support/Meeting Recorder/shares.json`),
   и потеря этого файла означает, что ссылку нельзя отозвать — она доживёт
   свой срок. Цена названа, а не спрятана.

Ключ публикации один на всех и **уезжает внутри приложения**, то есть
извлекается любым, кто его скачал (`plutil -p …/Info.plist`). Он гейтит только
**выпуск** ссылок: прочитать чужой шер им нельзя (содержимое под ключом,
которого нет ни здесь, ни в приложении), снять чужую публикацию нельзя (нужен
токен, а от него на сервере только SHA-256). Это порог выше «curl из скрипта»,
а не секрет; настоящая защита выпуска — токен на установку, и её нет. Смена
ключа = правка `/etc/propeller-share.env` и новая сборка **одновременно**,
иначе старые сборки перестают публиковать.

Реализация: один бинарь (Go, без CGO и без БД — шеры лежат файлами), systemd
с `Restart=always`. Сторона приложения: `PropellerPure/ShareCrypto.swift`,
`ShareLink.swift`, `SharePayload.swift` (чистое и покрытое тестами) и
`Sources/ShareService.swift` (сеть, Keychain, список публикаций).
