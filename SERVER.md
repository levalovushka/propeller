## 2. Что запущено

| сервис | как | конфиг |
|---|---|---|
| Caddy v2.11.4 | systemd `caddy`, слушает 80/443, TLS от Let's Encrypt автоматически | `/etc/caddy/Caddyfile` |
| Сайт | статика с диска | `/var/www/site` (владелец `deploy:deploy`); лендинг из `site/` этого репо |
| Сервис шеринга | **ещё не написан**; Caddy уже проксирует `/s/*` и `/api/*` на `localhost:8080` | — |

Caddyfile: `propeller.report` → статика; `/s/*` — заголовки
`X-Robots-Tag: noindex, nofollow` и `Cache-Control: private, no-store`, прокси
на :8080; `/api/*` — прокси на :8080; `www.` → 308 на голый домен. Общие
заголовки: `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`.
`robots.txt`: `Disallow: /s/`.

DNS (заведено 2026-08-24): A `@`/`www` → 201.24.53.31, AAAA `@` →
2a03:6f00:a::2:f155, NS Timeweb. Сертификат Let's Encrypt выпущен, продление
автоматическое (лог: `journalctl -u caddy`).

Деплой сайта — автоматический: push в `main`, трогающий `site/**`, запускает
`.github/workflows/deploy-site.yml` → rsync в `/var/www/site` от пользователя
`deploy` (вход только по CI-ключу; приватная часть — лишь в секрете
`DEPLOY_SSH_KEY` репо, host key сервера прибит в workflow). Руками:
`gh workflow run deploy-site.yml`. `site/robots.txt` обязан жить в репо —
деплой идёт с `--delete`, файлы мимо `site/` затираются. Netlify
(propellerapp.netlify.app) остаётся запасным. Git этого репо ходит в GitHub от
`levalovushka` (локальный `credential.helper` → gh; аккаунт llleva — не для
Propeller).

## 3. Механика шера — контракт (решение владельца 2026-08-24)

Ключевой принцип: **сервер не видит содержимого саммари** (E2E). Приватность
держится на конструкции, а не на обещаниях.

1. Приложение рендерит саммари в самодостаточный HTML, генерирует ключ K
   (32 байта), шифрует AES-GCM.
2. `POST /api/shares` (Bearer-секрет приложения из Keychain): блоб + TTL →
   сервер возвращает id = 16 случайных байт, base64url, 22 символа
   (перебор 2^128 — невозможен; плюс rate-limit на GET).
3. Ссылка: `https://propeller.report/s/<id>#k=<base64url K>` — фрагмент после
   `#` браузер на сервер не отправляет, ключ не попадает в логи.
4. Открытие: сервер отдаёт статичный вьюер, JS берёт ключ из `location.hash`,
   скачивает блоб, расшифровывает, показывает. Без JS страница не откроется —
   осознанный компромисс в пользу E2E.
5. Отзыв: `DELETE /api/shares/<id>`. Просроченное подметает сам сервис.
6. Несуществующая = просроченная = отозванная: **одинаковый 404** (нет оракула
   существования). Листинга шеров на сервере нет — список только локально
   в приложении.

Реализация: один бинарь (Go, ~300 строк) + SQLite, systemd с `Restart=always`,
слушает `localhost:8080`. Не написан; писать при подключении кнопки
«Поделиться» в приложении.
