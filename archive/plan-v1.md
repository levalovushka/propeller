# Транскрибатор встреч на GigaAM: план v1

Форк `meeting-recorder` под русский локальный транскрибатор на GigaAM-v3 (gigastt), с рекапом, простым выводом для коллег без Obsidian и раздачей через DMG.

## Контекст

База — форк `tonton-golio/meeting-recorder` (Swift, macOS 14+, Apple Silicon), полный контекст в [giga-transcriber-brief.md](giga-transcriber-brief.md). Продуктовые решения сверх брифа (подтверждены 2026-07-22, дистрибуция уточнена):

- **Дистрибуция:** DMG для небольшой команды. Sparkle и полноценная нотаризация — не обязательны для v1 (мало получателей, проще скинуть DMG). Подпись Developer ID — по возможности, чтобы Gatekeeper меньше ругался; иначе ad-hoc + инструкция «ПКМ → Открыть».
- **Вывод:** коллеги не пользуются Obsidian — нужен простой режим (читаемые транскрипт и рекап, без `[[wikilinks]]`/YAML), Obsidian-режим остаётся переключателем.
- **Рекап:** Ollama по умолчанию, API (Claude/OpenAI) опционально со своим ключом.
- **Автодетект:** только Zoom; браузерные встречи — ручной старт.
- **Язык:** только русский, ограничение приемлемо.

Бэклог идей со статусами — [product-ideas.md](../product-ideas.md), поддерживать актуальным по ходу работы. Архитектура приложения — [meeting-recorder/docs/ARCHITECTURE.md](../meeting-recorder/docs/ARCHITECTURE.md).

## Фазы (порядок важен)

### Фаза 0 — валидация главного риска (до любой обвязки)

Записать одну реальную Zoom-встречу существующим meeting-recorder (или взять готовый WAV), прогнать вручную через `gigastt serve` (`/v1/transcribe?segments=true&punctuation=true&itn=true`) и через FluidAudio-диаризацию. Сравнить head-модели `e2e_rnnt` vs `rnnt` на этой же записи.

**Verify:** качество ASR и диаризации на farfield/перебиваниях приемлемо; выбрана head-модель. Если диаризация плоха — вернуться к развилке №1 брифа (диаризация через gigastt) до продолжения.

### Фаза 1 — форк и базовая сборка

Форкнуть `tonton-golio/meeting-recorder`, собрать as-is, проверить запись/транскрипцию на WhisperKit (baseline).

**Verify:** приложение собирается и пишет встречу end-to-end.

### Фаза 2 — замена ASR (сердце миграции, шаги из брифа)

По разделу «Точка замены ASR» брифа: тип `ASRSegment {start, end, text}`, переписать `TranscriptionService.transcribeAudio()` на HTTP POST к `127.0.0.1:9876`, поправить сигнатуры `diarizeAndMatch()` / `mergeTranscriptionWithDiarization()`, выкинуть WhisperKit из `Package.swift` и языковую логику (фиксируем `ru`). Диаризацию FluidAudio не трогать.

**Verify:** транскрипт реальной записи с диаризацией и матчингом спикеров, качество не хуже Фазы 0.

### Фаза 3 — sidecar-менеджмент gigastt

Забандлить бинарник в `.app`, спаун `gigastt serve` при старте / kill при выходе, health-check, обработка падений (рестарт), автозагрузка модели ~225 МБ на первом запуске с прогрессом в UI. Fallback: CLI-режим `gigastt transcribe`, если сервер нестабилен.

**Verify:** холодный старт на чистой машине: приложение само поднимает сервер, качает модель, транскрибирует; после quit не остаётся процессов-сирот.

### Фаза 4 — простой режим вывода (новое, вне брифа)

Рядом с `MarkdownWriter.swift` — переключатель формата в настройках: «Obsidian» (как есть) / «Простой» (читаемый `.md`: заголовок, участники, транскрипт по спикерам с таймстемпами; без YAML и wikilinks). Кнопка «скопировать транскрипт/рекап» для «скинуть в чат». Простой режим — дефолт для раздачи.

**Verify:** оба формата генерируются с одной записи, простой читается в любом просмотрщике.

### Фаза 5 — LLM-рекап

Новый слой поверх готового `.md`: настраиваемый промпт, провайдер Ollama (дефолт, авто-обнаружение `localhost:11434`) или API (Claude/OpenAI, ключ в Keychain). Результат — `recap.md` рядом с транскриптом, в выбранном формате вывода. Если Ollama нет и ключ не задан — рекап тихо пропускается с подсказкой в UI.

**Дефолтный промпт:** явно просить подчищать ASR-артефакты (искажённые имена/термины, обрывки на границах реплик) по контексту, не выдумывая факты.

**Verify:** рекап генерируется обоими провайдерами; при отсутствии обоих приложение не ломается.

### Фаза 6 — автодетект Zoom

Наблюдение за процессом Zoom → авто-старт записи, авто-стоп по завершении звонка. Настройка: **Auto-record / Off** (дефолт Auto). Без диалога подтверждения: системное уведомление с действием «Не записывать» (отмена + удаление частичной записи). Остановка также из менюбара / окна / ⌘R.

Сигналы встречи: `aomhost` **или** meeting-window **или** display-sleep assertion; `caphost` / просто запущенный `zoom.us` — не встреча.

**Verify:** старт Zoom-звонка триггерит запись + уведомление; «Не записывать» удаляет запись; конец звонка — стоп и обработка.

### Фаза 7 — раздача через DMG _(ждём)_

Для небольшой команды достаточно скинуть DMG — без Sparkle и без обязательной нотаризации.

1. Скрипт упаковки `.app` → `.dmg` (drag-to-Applications).
2. Подпись Developer ID + нотаризация — **опционально**, если Gatekeeper мешает; иначе ad-hoc и короткая инструкция «ПКМ → Открыть».
3. README для коллег: скачал → в Applications → разрешения (Микрофон, Запись экрана) → Zoom Auto/Off.
4. Sparkle / авто-апдейты — **отложено** (мало получателей, проще переслать новый DMG).

**Verify:** коллега открыл DMG, запустил приложение, записал встречу, получил транскрипт.

## Риски и что за ними следить

- **Диаризация на реальном Zoom** — снимается Фазой 0 до основной работы.
- **Подпись sidecar gigastt** — всплывёт только если пойдём в Developer ID / нотаризацию.
- **gigastt молодой** — проверить стабильность CoreML EP в Фазе 0; fallback на CLI-режим предусмотрен в Фазе 3.
