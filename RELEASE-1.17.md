# Релиз 1.17 — улучшенное саммари

Единый релиз (решено 2026-08-13): детерминированная генерация, механическая
сборка для длинных встреч, ансамбль для содержательных. Дыр, где можно тихо
ошибиться, много, поэтому готовность проверяется гейтами: каждый ловит свой
класс ошибок, на следующий не переходим, пока текущий не зелёный.

Основание — замеры в [tools/recap-lab/OPTIMIZATION.md](tools/recap-lab/OPTIMIZATION.md):
ансамбль 11,4 из 14 против базы 8,2 (p = 1,2 %), механическая сборка спасает
3–5 пунктов на схлопнувшихся сводах, t=0 детерминирован побайтово на двух встречах.

## Что едет

| изменение | что даёт |
|---|---|
| `temperature 0` + один ретрай при t=0,3, если ответ схлопнулся | пол поднимается с 4 до 8 пунктов, результат воспроизводим |
| механическая сборка facts → конспект (переполняющие встречи) | свод больше не схлопывается: в нём нет генерации |
| ансамбль с объединением (встречи ≥15 мин, влезающие в окно) | +3–4 пункта полноты за 4–6 вызовов |
| версия генератора в метаданных конспекта | телеметрия по версиям, безопасный бэкфилл, откат |
| телеметрия генерации | reply_tokens, retried/collapsed, длительность, число пунктов, версия, RAM-когорта |
| прогресс по веткам ансамбля в UI | 2 минуты генерации не выглядят зависанием |

## Что НЕ едет (решено, не забыто)

- Старые конспекты не перегенерируются **никогда** — ни бэкфиллом, ни вручную.
  Бэкфилл догоняет только встречи без конспекта.
- Кнопки «Сгенерировать заново» нет и не появляется: при t=0 повтор — тот же текст.
- Выдумки не чиним (у ансамбля их больше: 2,0 находки против 1,0) — только считаем
  в телеметрии.
- 9B не тащим: +0,7 пункта в честном замере не стоят 3,2 ГБ (OPTIMIZATION.md, пункт «б»).

## Правила маршрутизации

| встреча | путь |
|---|---|
| < 15 мин | одиночный проход, t=0 + ретрай |
| ≥ 15 мин, влезает в окно, машина ≥16 ГБ RAM | ансамбль: t=0 целиком · сэмпл t=0,7 целиком · chunk-facts; слияние и рендер — код |
| ≥ 15 мин, машина <16 ГБ | одиночный проход, t=0 + ретрай (решено 2026-08-13: у части юзеров 8 ГБ, и они уже страдают) |
| не влезает в окно | нарезка + механическая сборка (без ансамбля) |
| notes пользователя | только в слияние; ветки их не видят, текст заметок не переписывается |

## Риски, известные до старта

**1. У `t=0` есть режим конфабуляции, и детерминизм его запирает.** На
`20260810_094722` (планёрка) детерминированный ответ не просто короче порога — он
придумывает участника: «Ильяс» становится «Ильёй Сафроновым», фамилии в транскрипте
нет ни разу, пять вхождений на конспект, и этому человеку назначаются задачи. Повтор
при t=0 вернёт то же слово в слово. Строка «пол 4 → 8» в «Что едет» держится
**только вместе с ретраем**, и ретрай в плане уже есть — но замером показано, что
одного повтора мало: порог берут 2 сэмпла из 5 (A5.2, `OPTIMIZATION.md`). Перед
портом решить, сколько попыток даёт одиночный путь.

**2. Дыра, которая есть в проде уже сегодня.** Одиночный путь 1.16 имена не
фильтрует: выдуманная фамилия доезжает до пользователя как есть. Ансамбль в 1.17
фильтрует **добавки** проверкой заземления, но черновик не трогает — то есть эта
дыра переезжает в 1.17 вместе с черновиком.

**3. Кандидат в телеметрию этапа 1:** доля имён конспекта, отсутствующих в
транскрипте **и** в календарных полях встречи. Считается без модели, показывает
масштаб дыры на реальных встречах, а не на трёх размеченных.

**4. Расширять ли прод-`grounded()` на имена — отдельное решение владельца, в план
не вносится.** Цена известна и немаленькая: ASR коверкает имена участников
(«Левон» → «Льон», «Льва»), и фильтр по именам начнёт резать живых людей. На m3
таких ложных срабатываний 4–6 на конспект против 1 настоящей выдумки.

## Гейты

### Г0 · Стенд закрыт (recap-lab)

- [ ] Слияние/дедуп: ≤14 пунктов при покрытии ≥11, чередованный замер n≥5
      → **гейт №1 проведён и не пройден (2026-08-13).** Критерий переформулирован
      заранее и записан до прогонов; замер — живые батчи ABAB, n = 8 на трёх
      встречах, третья размечена вслепую. Разницы `code14` против базы:
      **+2,38 · +1,25 · −1,62**, пулом p = 23,7 % (тем же вердиктом и до починки
      матчера). Третья встреча нашла дыру конструкции: черновик t=0 схлопывается
      детерминированно (684 токена, 8/8), теряет «Ход обсуждения» и даёт 6/21 —
      ниже всего распределения сэмплов базы. Конструкция изменена (ветка-черновик
      получила ретрай при t=0,3), но **замером показано, что одного повтора мало**:
      порог берут 2 сэмпла из 5. Гейт №2 не запускался по стоп-условию. Плюс
      отдельная проблема шкалы: сверка матчера на третьей встрече **67 %** против
      96–100 % на первых двух, третий стратум недопустим, а якоря подгонять нельзя.
      Разбор и три предложения — в A5.2 `tools/recap-lab/OPTIMIZATION.md`
- [x] Ансамбль держит эффект на второй встрече (20260812_153107) — A5.3, +2,6,
      p = 0,4 %, и ещё дважды подтверждено в батчах A5.2
- [x] Сверка матчера воспроизводима командой для обеих встреч —

### Г1 · Swift-порт с паритетом

Самый вероятный источник тихой ошибки — перенос. Парсер facts на стенде уже
один раз молча съел половину строк и чуть не перевернул вывод эксперимента.

- [ ] Fixture-тесты: парсер facts, слияние, дедуп, рендер — те же входы из
      `tools/recap-lab/out/` → те же пункты, что у python-версии
- [ ] Отдельный тест на обе формы вывода экстрактора («МЕТКА: раз; два» одной
      строкой и «МЕТКА:» + буллеты)
- [ ] Промпты перенесены побайтово. Любое «улучшение по пути» = немерянный промпт

### Г2 · Юнит-тесты новой логики

- [ ] Порог 15 минут: 14:59 → одиночный, 15:01 → ансамбль
- [ ] Переполнение окна → нарезка + механическая сборка, не ансамбль
- [ ] Ретрай: только при схлопывании, только один, только t=0,3; при t=0 повторного
      вызова с t=0 не бывает
- [ ] Notes: в слиянии есть, в ветках нет
- [ ] Версия генератора пишется в метаданные нового конспекта
- [ ] Бэкфилл пропускает встречу с конспектом любой версии
- [ ] Один `num_ctx` на все ветки ансамбля (смена окна = перезагрузка модели)
- [ ] `Task.checkCancellation` между вызовами веток
- [ ] Упавшая ветка → конспект из оставшихся, не ошибка
- [ ] Полный сьют проекта зелёный (`./build.sh` + тесты)

### Г3 · Сценарная прогонка руками (живое приложение)

Любой fail = will-hurt. Дополняет [dogfood-checklist.md](dogfood-checklist.md).

- [ ] Встреча <15 мин → одиночный t=0, время не выросло
