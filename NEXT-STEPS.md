## Что в полёте: `StemMerge` написан, но не подключён

`PropellerPure/StemMerge.swift` + `StemMergeTests` (9 тестов, зелёные) собирают одну
ленту из двух дорожек: микрофон после `EchoDedup` — владелец по построению,
системный стем — все остальные. Реплики разных людей не сливаются никогда.

**Подключения в `TranscriptionService` нет.** Офлайн-путь по-прежнему читает микс.

### Что для этого нужно

1. `TranscriptionService.transcribe(audioURL:)` — вместо одного прохода по миксу
   два: `<id>.mic.wav` и `<id>.sys.wav`.
2. Диаризация — **только по системному стему**: владельца там нет, и ей больше не
   надо отделять его голос от эха.
3. Микрофонные реплики пропустить через `EchoDedup` (он потоковый — в офлайне
   сегменты подаются по времени встречи, как в `scratchpad/step0/dedup/main.swift`
   той сессии; логика переиспользуется, не переписывается).
4. Склейка — `StemMerge.merge(owner:others:)`.
5. **Запасной путь обязателен**: нет стемов (запись только с микрофона, старый
   архив) — работать как сейчас, по миксу.

### Приёмка — числами, а не на глаз

На дорожках тестировщика (`~/Desktop/20260812_134834.{mic,sys}.wav`, 17 минут,
колонки) сейчас: **28 смешанных строк из 264 (10.6 %)**. После подключения должно
стать 0 — по построению. Плюс покрытие чужой речи на колонках должно подняться с
58.5 % к уровню чистого стема.

Как получить те же числа заново (транскрипты лежали в `/private/tmp`, они не
переживут перезагрузку — команда воспроизводит их):

```bash
D=~/Desktop; W=/tmp/attrib; mkdir -p $W
ffmpeg -y -i $D/20260812_134834.mic.wav -i $D/20260812_134834.sys.wav \
  -filter_complex "[0:a][1:a]amix=inputs=2:duration=longest:normalize=0[a]" \
  -map "[a]" -ac 1 -ar 16000 $W/colleague.mix.wav
cp $D/20260812_134834.mic.wav $W/colleague.mic.wav
cp $D/20260812_134834.sys.wav $W/colleague.sys.wav
for t in mix mic sys; do
  /Applications/Propeller.app/Contents/MacOS/gigastt transcribe --offline \
    --model-dir "$HOME/Library/Application Support/Meeting Recorder/gigastt-models" \
    --hotwords-file "$HOME/Library/Application Support/Meeting Recorder/hotwords.txt" \
    -f srt -o $W/colleague.$t.srt $W/colleague.$t.wav
done
python3 tools/echo-probe/ownership.py $W colleague
```

`ownership.py` сравнивает **сырой** микрофон; чтобы получить 10.6 %, микрофон надо
сначала прогнать через `EchoDedup` (иначе эхо делает смешанной каждую строку — на
этой записи две трети микрофонной дорожки чужие). Драйвер дедупа собирается так:

```bash
cd meeting-recorder/swift
swiftc -O PropellerPure/*.swift <драйвер>.swift -o /tmp/dedup   # internal становится доступен
```

## Опровергнуто замером — не переоткрывать

- **Длинный промпт конспекта.** 2525 → 5183 символа правил: решений 28 → 18, три
  встречи из восьми вообще без решений. На 4B-модели длина конкурирует с полнотой.
- **Микс теряет слова.** На четырёх встречах целиком микс доносит 89–95 % обеих
  сторон. Исключение одно — колонки («Обед» 58.5 %).
- **Метрика смешанных строк по времени.** Давала 68–87 %, а на заведомо
  правильной ленте даёт 96–99 %: сегменты ASR покрывают почти всё время встречи.
  Правильная мера — по словам (`ownership.py`), и она даёт 10.6 %.
- **VAD против мусора в начале записей.** С `--vad` та же каша: там плохой звук,
  а не тишина.
- **Фонетическая коррекция по индексу словаря.** 8 срабатываний, 6 из них — порча
  правильного текста. Метод рассчитан на каталоги в миллионы имён.
- **Детерминированное вырезание выдуманных сроков.** Отклонено владельцем: зацепит
  лишнее. Сроки остаются задачей редактора.
