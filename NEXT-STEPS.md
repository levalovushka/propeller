## ⚠️ Прочитать первым: не обрывать запись

**Перед `./build.sh`, `osascript quit`, `open -a Propeller` — проверить, не идёт ли запись.**
`build.sh` делает `rm -rf /Applications/Propeller.app`, а quit прерывает встречу; авто-запись
после этого начинает новую, и одна встреча остаётся в архиве несколькими обрывками.

```bash
python3 -c "import json,pathlib;r=json.loads((pathlib.Path.home()/'.meeting-recorder/recordings/recordings.json').read_text());r=r if isinstance(r,list) else r.get('recordings',r);a=[x for x in r if x.get('status')=='recording'];print('идёт запись:',a[0]['id'] if a else 'нет')"
```

Так уже случилось 2026-08-11: встреча «Дом Пряжи | Оценка КП» разрезана на четыре части
(`20260811_121132` 71 с, `20260811_121253` 58 с, `20260811_121359` 76 с, `20260811_121526`).
Данные целы (`saved`, файлы полной длины, quit-flush сработал), но фрагменты остаются
отдельными встречами: механизма склейки в приложении нет, `reprocess` недостижим из
интерфейса. Свести можно только вручную, скопировав текст, когда все обработаются.

   записывалось как сбой — ложный провал саммари в телеметрии, «retry in 19s» и пробуждение
   планировщика ради встречи, которой нет. Сценарий воспроизводится только руками, поэтому
   подтверждение — следующее реальное удаление: в логе не должно быть `failed (attempt`.
