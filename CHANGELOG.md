Что накопилось с последнего релиза. Отсюда собираются заметки к релизу на GitHub —
тот же голос: короткие русские пункты, сгруппированные по «Новое» / «Фиксы» /
«Внутреннее». Заметки уже выпущенных версий живут в
[Releases](https://github.com/levalovushka/propeller/releases) и сюда не копируются.

**Правило:** поменял поведение — строка сюда в том же коммите. Иначе перед релизом
приходится восстанавливать список по `git log`, а туда попадает не то, что человек
заметит, а то, что было тяжело писать.

## Не выпущено (после 1.13.1)

### Фиксы

- **Обновления проверяются раз в час, а не раз в сутки.** Sparkle по умолчанию ходит
  за фидом раз в 24 часа; для сборки, которая может нести дефект без обходного пути,
  это слишком долго — 1.13 ломала любую встречу длиннее 25 минут, фикс существовал
  через четыре часа, а человек с 1.13 узнать об этом не мог. Час — это минимум,
  который Sparkle вообще разрешает.

### Внутреннее (пользователь не видит)

- **Каталог состояний UI как данные** — `PropellerPure/UIStateCatalog.swift`, 41
  состояние, полнота проверяется тестом против типов: у каждой стадии пайплайна есть
  экран или явная пометка «недостижима».
- **Галерея состояний и экспортёр** — `./build.sh --gallery` вкомпиливает окно со
  всеми экранами и режим `--gallery-export`, который снимает их в PNG. В обычной
  сборке нет ни байта. Подробности и порядок работы — [design/state-gallery.md](design/state-gallery.md).
- **Фикстурный архив для съёмки** — `Sources/GalleryFixture.swift`: временный архив с
  настоящими файлами, на который переключается процесс на время экспорта. Без него
  двенадцать состояний рисовали свой пустой вариант (саммари, письмо и транскрипт
  читаются с диска), и 21 кадр из 41 выходил попиксельно одинаковым. Побочно из
  кадров ушёл реальный архив пользователя.
- **Экспортёр сам ищет дубли** — считает хеши снятого и печатает группы одинаковых
  кадров. Состояние, которое фотографируется как соседнее, справочником не
  документируется, а глазами в папке из сорока миниатюр это не видно.

## Как готовить релиз

1. Пробежать этот файл, перенести пункты в заметки релиза (Фиксы / Новое; «Внутреннее»
   обычно не идёт наружу).
2. Бампнуть версию в `meeting-recorder/swift/build.sh` (`CFBundleShortVersionString`
   **и** `CFBundleVersion`), собрать, упаковать `./package-dmg.sh`, сделать
   `./make-appcast.sh`.
3. Выложить в GitHub Release **и DMG, и `appcast.xml`** — имена ассетов должны
   совпадать с `enclosure url` в фиде, иначе Sparkle получит 404.
4. Здесь оставить пустой раздел «Не выпущено».

Заметки прошлых релизов заканчиваются блоком «Установка / апдейт» — про
«Проверить обновления…» и про ПКМ→Открыть на первом запуске. Он нужен каждый раз,
пока нет Developer ID и нотаризации.
