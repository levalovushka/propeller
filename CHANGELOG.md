# Changelog

Что накопилось с последнего релиза. Отсюда собираются заметки к релизу на GitHub —
тот же голос: короткие русские пункты, сгруппированные по «Новое» / «Фиксы» /
«Внутреннее». Заметки уже выпущенных версий живут в
[Releases](https://github.com/levalovushka/propeller/releases) и сюда не копируются.

**Правило:** поменял поведение — строка сюда в том же коммите. Иначе перед релизом
приходится восстанавливать список по `git log`, а туда попадает не то, что человек
заметит, а то, что было тяжело писать.

## Не выпущено (после 1.16.4)

_1.16.4 был срезан из ворктри мимо этого файла (см. коммит 91e6090) и увёз один
фикс автозаписи; `build.sh` уже стоит на 1.16.5 как следующем номере._

### Новое

- Расшифровка читает микрофон и звук встречи по отдельности, а не сведённой
  дорожкой. На колонках это меняет главное: раньше слова собеседника, сказанные
  одновременно с вашими, до расшифровки не доходили — на часовой встрече доходило
  57 % его слов, теперь все. Заодно из ваших реплик уходит эхо: «Вот» и «Миграцию»
  сказанные собеседником, больше не подписаны вашим именем.

- Расшифровка знает, кого позвали на встречу. Имена участников и название из
  календаря подсказываются распознавателю на этой встрече и только на ней, так
  что фамилии перестают превращаться в похожие обычные слова. Имена берутся из
  адресов вида `имя.фамилия`; там, где по написанию не видно, «Дмитрий» или
  «Дмитрый», подсказка не ставится вовсе.

- Конспект стал воспроизводимым: одна и та же встреча даёт один и тот же текст,
  слово в слово. А обрывок вместо конспекта — модель иногда бросает ответ на
  трети — теперь распознаётся по длине и пересчитывается, один раз и сразу.

- Длинная встреча, которая не помещается в окно модели, читается по фрагментам:
  из каждого выписываются факты, а конспект по ним пишется одним заходом — так
  же, как у обычной встречи, с «Итогом» и связным текстом. Пока считается, в
  деталях активности видно, какой фрагмент в работе — минуты генерации больше не
  выглядят зависанием. Если модель на последнем шаге сорвётся и выбросит
  найденное, конспект соберётся из тех же фактов кодом: он будет суше и без
  «Итога», но ни один пункт не пропадёт.

## Как готовить релиз

1. Пробежать этот файл, перенести пункты в заметки релиза (Фиксы / Новое; «Внутреннее»
   обычно не идёт наружу).
2. Бампнуть версию в `meeting-recorder/swift/build.sh` (`CFBundleShortVersionString`
   **и** `CFBundleVersion`), затем в `meeting-recorder/swift` подряд:
   `./build.sh && ./notarize.sh && ./package-dmg.sh && ./make-appcast.sh`.
   Порядок не переставлять: `notarize.sh` стейплит тикет **в `.app`**, а
   `package-dmg.sh` запечатывает уже подписанное приложение в образ и нотаризует
   образ отдельно. `make-appcast.sh` идёт последним — он подписывает EdDSA по
   байтам DMG, а staple эти байты меняет.
3. Выложить в GitHub Release **три ассета**: DMG с версией в имени, `Propeller.dmg`
   и `appcast.xml`. Имя версионного обязано совпадать с `enclosure url` в фиде,
   иначе Sparkle получит 404; `Propeller.dmg` — тот же образ под вечным именем,
   его `package-dmg.sh` кладёт рядом жёсткой ссылкой. Кнопка «Скачать» на лендинге
   ведёт на `releases/latest/download/Propeller.dmg` и не правится от релиза к
   релизу — но только пока этот ассет выкладывают каждый раз.
4. Здесь оставить пустой раздел «Не выпущено».

Заметки прошлых релизов заканчиваются блоком «Установка / апдейт» — про
«Проверить обновления…». Абзаца про ПКМ→Открыть там больше нет: с 1.16.5 сборка
подписана Developer ID и нотаризована, первый запуск — двойной клик.
