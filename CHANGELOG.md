## Как готовить релиз

1. Пробежать этот файл, перенести пункты в заметки релиза (Фиксы / Новое; «Внутреннее»
   обычно не идёт наружу). **Заметки лечь должны в `dist/RELEASE-<версия>-NOTES.md`
   до шага 3** — `make-appcast.sh` вкладывает этот файл в фид, и именно его человек
   читает в окне обновления. Нет файла — скрипт скажет об этом последней строкой, и
   окно будет пустым.
2. Бампнуть версию в `meeting-recorder/swift/build.sh` (`CFBundleShortVersionString`
   **и** `CFBundleVersion`).
3. В `meeting-recorder/swift` подряд:
   `./build.sh && ./notarize.sh && ./package-dmg.sh && ./make-appcast.sh`.
   Порядок не переставлять: `notarize.sh` стейплит тикет **в `.app`**, а
   `package-dmg.sh` запечатывает уже подписанное приложение в образ и нотаризует
   образ отдельно. `make-appcast.sh` идёт последним — он подписывает EdDSA по
   байтам DMG, а staple эти байты меняет.
4. **Не чистить `dist/` перед сборкой.** Дельта-патчи считаются из образов
   предыдущих релизов, которые там лежат: пустой `dist/` — это молчаливый релиз
   без патчей (скрипт предупредит одной строкой, но не остановится), то есть все
   снова качают 282 МБ. Пять последних образов достаточно.
5. Выложить в GitHub Release **всё, что напечатал `make-appcast.sh`** — он печатает
   готовую строку `gh release upload`. Это версионный DMG, `Propeller.dmg`,
   `appcast.xml` и по одному `.delta` на каждый предыдущий образ. Имена обязаны
   совпадать с `enclosure url` в фиде: пропущенный патч не смертелен (клиент
   возьмёт полный образ), переименованный — 404 и сорванное обновление.
   `Propeller.dmg` — тот же образ под вечным именем, кнопка «Скачать» на лендинге
   ведёт на него и не правится от релиза к релизу.
6. **Если релиз чинит то, с чем люди живут — пометить критическим:**
   `CRITICAL_FOR=<первая версия с фиксом> ./make-appcast.sh` (или `CRITICAL_FOR=all`).
   Это единственное, что делает часовую проверку фида осмысленной: пока патч не
   скачан, Sparkle спрашивает фид раз в час, а как только патч лёг на диск,
   следующий цикл планируется как `MAX(час, неделя)` для обычного релиза и
   `MIN(час, неделя)` для критического. То есть разница между «увидит фикс в
   течение часа» и «увидит через неделю». На установку это не влияет никак: она
   всё равно происходит при следующем выходе из приложения.
7. **Убедиться, что этот релиз — «latest».** Фид лежит по
   `releases/latest/download/appcast.xml`, поэтому черновик или pre-release
   выглядит опубликованным, а Sparkle продолжает отдавать прошлую версию:

   ```bash
   curl -sL https://github.com/levalovushka/propeller/releases/latest/download/appcast.xml | grep -E 'shortVersionString|deltaFrom'
   ```

   Версия должна быть новой, а строк `deltaFrom` — столько же, сколько патчей
   выложено. Каждый патч дополнительно проверяется на доступность — `make-appcast.sh`
   печатает готовые `curl` по всем; 404 значит, что ассет не доехал или переименован.
8. Здесь оставить пустой раздел «Не выпущено».

**Фид руками не правится.** Каждая строка в нём подписана EdDSA по байтам файла;
после ручной правки подписи разъезжаются, и обновление отваливается у всех. Любое
изменение — перезапуск `make-appcast.sh`. Он же перед печатью применяет каждый патч
к тому образу, который тот патчит, и сверяет результат с приложением этого релиза
(105 файлов по sha256, права, симлинки, `codesign`, `stapler`); прогон — 18 с.
`VERIFY_DELTAS=0` эту проверку снимает и годится только для отладки самого скрипта.

Заметки прошлых релизов заканчиваются блоком «Установка / апдейт» — про
«Проверить обновления…». Абзаца про ПКМ→Открыть там больше нет: с 1.16.5 сборка
подписана Developer ID и нотаризована, первый запуск — двойной клик. С 1.16.8
установленный Propeller забирает патч в фоне и ставит его при следующем выходе из
приложения, так что «обновится сам» — теперь буквально.
